# ADR-013: Читаемый номер заявки (дата + порядковый номер)

**Статус:** Принято
**Дата:** 2026-08-31
**Задача:** ЧТЗ_Читаемый_номер_заявки.md

## Контекст

Заявки идентифицируются cuid (`cmth2zams0000oys244tvvfbi`) — нечитаемо для
оператора в письмах/Telegram и для клиента. Нужен человекочитаемый номер:
дата подачи + порядковый номер через дефис, счётчик с 1 и до бесконечности.

## Решение

Формат: **`ГГГГММДД-N`** (например `20260831-5`), где N — глобальный сквозной
счётчик, НЕ сбрасывается по дням.

### Генерация N — sequence PostgreSQL (не приложение)

Колонка `Order.number Int @unique @default(autoincrement())` — Prisma создаст
sequence. Обоснование против альтернатив:

| Вариант | Пreject |
|---------|---------|
| `MAX(number)+1` в приложении | гонка при параллельных заявках |
| Redis `INCR` | теряется при сбое/очистке Redis; ещё одна зависимость |
| **PG sequence** ✅ | атомарно, переживает рестарты, нулевая цена (уже есть PG) |

### Не храним отображаемый номер

`20260831-5` НЕ хранится в БД — вычисляется в коде из `number` + `createdAt`
(денормализация не нужна: дата уже есть). Helper: `src/lib/orderNumber.ts`.

Часовой пояс даты — **Europe/Moscow** (+3), чтобы день в номере совпадал с
днём подачи клиентом.

### Существующие заявки

При миграции колонка SERIAL проставит существующим строкам номера 1..K,
счётчик продолжится с K+1 — соответствует «с 1 и до бесконечности».
