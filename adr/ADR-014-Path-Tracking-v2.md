# ADR-014: Трекинг пути клиента v2 (landing, переходы, engagement)

**Дата:** 2026-10-14
**Статус:** Accepted
**Контекст:** Владельцу нужно видеть во внешней Grafana движение клиента по сайту:
страница входа, переходы между страницами, статистика таких переходов, клики по
телефону и WhatsApp, устройства, UTM-источники визитов, время на странице; окна
24ч + 7д. Текущие ограничения (ADR-002): сессии склеиваются по IP+30 мин (NAT
склеивает разных людей, смена IP мобильного рвёт сессию), повторный просмотр
той же страницы за сессию вырезается дедупом, `from→to` не фиксируется,
UTM пишутся только в Order, клики `wa.me` не ловятся, устройств нет.

## Решение

Расширить существующий контур (Visit + /api/visit + /metrics/tracking) до v2 —
без новых таблиц, эндпоинтов и портов.

### 1. Анонимные клиентские ID (не ПД, 152-ФЗ ок)

| ID | Хранилище | Жизнь | Назначение |
|---|---|---|---|
| `sessionId` | sessionStorage | вкладка | сессия = цепочка просмотров во вкладке (замена IP-склейки) |
| `visitorId` | localStorage | ~180 дней | новые/вернувшиеся посетители |
| `viewId` | — | один просмотр | ключ для обновления `dwellMs` (leave-beacon) |

Все — `crypto.randomUUID()`, генерируются на клиенте, ПД не содержат.

### 2. Буфер обмена трекинга (клиент)

- `enter`-beacon на каждую навигацию: `{ type:'enter', page, from, sessionId,
  visitorId, viewId, referrer?, utmSource?, utmMedium?, utmCampaign? }`;
  `referrer`+`utm` — только на входе (первая страница во вкладке, UTM из
  `location.search` посадочной страницы).
- `leave`-beacon на `pagehide`/`visibilitychange=hidden`: `{ type:'leave',
  viewId, dwellMs }` — точное время на странице (включая последнюю).
- Дедуп: только перезагрузка той же страницы < 30 с (F5-шум); возвраты и
  полные пути пишутся. Старый дедуп `visit:<page>` удаляется.
- Транспорт тот же (fetch keepalive / sendBeacon).

### 3. Схема БД (обратно совместимо, только nullable-колонки)

```prisma
model Visit {
  // ...существующие поля...
  sessionId   String?  // сессия вкладки
  visitorId   String?  // постоянный анонимный ID
  viewId      String?  @unique // ключ leave-обновления
  fromPage    String?  // предыдущая страница (null = вход)
  utmSource   String?
  utmMedium   String?
  utmCampaign String?
  device      String?  // mobile | tablet | desktop (server-side из UA)
  dwellMs     Int?     // время на странице (leave-beacon)

  @@index([sessionId])
  @@index([visitorId, createdAt])
}
// ClickEvent += device String? (разрез кликов по устройству)
```

### 4. Сервер

- `POST /api/visit` v2: Zod (union `enter|leave`, старый payload валиден как
  enter без полей); `leave` → `updateMany({ where:{ viewId } })` (идемпотентно,
  0 строк = ignore). Rate-limit: дефолт `RATE_LIMIT_VISIT_PER_HOUR` 120 → 240.
- `src/lib/device.ts` — определение устройства из UA (regex, без новых зависимостей).
- Сессии: `sessionizeVisits` группирует по `sessionId`, при отсутствии — по
  нормализованному IP (легаси-строки ADR-002 продолжают учитываться).

### 5. Экспорт `/metrics/tracking` v2

Окна 24ч+7д добавляются к ключевым гейджам; срезы — топ-10 (+`other`), пары
`from→to` — топ-10 пар. Новое (весь список — в ЧТЗ):

- `business_landing_pages_{24h,7d}{page}` — страницы входа
- `business_page_transitions_24h{from,to}` — переходы внутри сайта
- `business_entry_flows_24h{source,landing}` — источник × посадочная
- `business_exit_pages_{24h,7d}{page}` — страницы выхода
- `business_devices_{24h,7d}{device}`; `business_visitors_returning_{24h,7d}`
- `business_whatsapp_clicks_{12h,7d}` + события с timestamp (паттерн phone)
- `business_funnel_{24h,7d}{stage}`: visit → content_view → contact_click → lead
  (по distinct sessionId; lead — абсолютное число Order)
- `business_avg_time_on_page_{24h,7d}`, `business_avg_pages_per_session_{24h,7d}`
- `business_top_dwell_pages_24h{page}` — топ-5 страниц по времени

Инфраструктура мониторинга не меняется: те же эндпоинт, ключ, интервал скрейпа.

### 6. Grafana

Локальный дашборд `business-metrics.json` дополняется панелями (воронка,
landing, переходы, устройства, WhatsApp). Внешней стороне (владельцу
мониторинга) — мини-ЧТЗ только на новые панели; Prometheus подхватит метрики
автоматически (SD, config не меняется).

## Альтернативы

### Вариант А: Расширение Visit + те же эндпоинты — ВЫБРАН
- **Плюсы:** один источник правды «просмотры»; переиспользуется весь контур
  (Zod, rate-limit, Prometheus-рендер, дашборды); миграция только добавляет
  nullable-колонки; обратная совместимость payload.
- **Минусы:** семантика Visit шире «визита» (становится pageview); объём растёт.
- **Оценка:** 8/10

### Вариант Б: Новые таблицы PageView + Session
- **Плюсы:** чистая семантика; сессии как сущность.
- **Минусы:** два источника правды по просмотрам; перенос логики и дашбордов;
  миграция данных; вдвое больше кода при тех же метриках.
- **Оценка:** 6/10

### Вариант В: Полагаться на Яндекс.Метрику (API) для пути
- **Плюсы:** ноль кода трекинга на сайте.
- **Минусы:** путь недоступен в Prometheus внешнего мониторинга; квоты/лаги API
  Метрики; adblock-феномен искажает; владелец хочет метрики в своей Grafana.
- **Оценка:** 3/10

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Рост Visit (каждая навигация) | Средняя | Низкое | узкая таблица; rate-limit 240/ч; leave — UPDATE, не INSERT; опциональная чистка >180д (отдельная задача) |
| Adblock/приватный режим режут beacon | Средняя | Низкое | индикативные метрики; fallback — IP-сессии легаси-строк |
| sessionStorage = сессия на вкладку (несколько вкладок = 2 сессии) | Высокая | Низкое | стандарт аналитики (Метрика так же); visitorId связывает |
| leave раньше enter (гонка) | Низкая | Низкое | updateMany идемпотентен; 0 строк = ignore |
| Кардинальность лейблов | Средняя | Среднее | топ-10+other везде; пары — топ-10; следы в рендере ограничены |
| 152-ФЗ | Низкая | Высокое | только случайные uuid, без ПД; чекбокс согласия не затрагивается |

## Критерии успеха

- [ ] Каждый переход страницы фиксируется в Visit с `from→to` и `sessionId`
- [ ] Landing/переходы/воронка/устройства/WhatsApp/dwell видны в `/metrics/tracking`
- [ ] Старые панели Grafana не сломаны, новые добавлены (локально)
- [ ] Совместимость: старый payload /api/visit принимается
- [ ] `npm run test && npm run lint && npx tsc --noEmit` — зелёные
