# ADR-003: Гео-посадочные SEO-страницы (районы Москвы ВАО/ЮАО/ЮВАО + города МО ≤30 км)

**Дата:** 2026-08-25
**Статус:** Accepted
**Контекст:** Для роста видимости в Яндексе по гео-запросам («эвакуатор марьино»,
«эвакуатор люберцы») нужны посадочные под районы Москвы (восток, юг, юго-восток —
41 район) и города ближнего Подмосковья ≤30 км от МКАД по тем же направлениям
(~27 городов). Пользователь выбрал максимальный охват: страница на каждый район
+ города с посёлками. Существующая инфраструктура: реестр посадочных
`src/config/service-pages/`, универсальный SSG-шаблон `ServicePage`, роут
`(services)/[slug]`, автогенерация sitemap. Гео-пилот — страница «Видное».

## Решение

Data-driven гео-модуль `src/config/geo/` поверх существующего шаблона:
структурированные данные локаций → композер → `ServicePageConfig` → единый
реестр `landingPages`. Рендер, роутинг, sitemap, JSON-LD — переиспользуются.

### Компоненты:

1. **`src/config/geo/types.ts`** — тип `GeoLocality`: слаг, название, направление
   (vao/yuao/yuvao/mo-vostok/mo-yugo-vostok/mo-yug), тип (district/city/hub),
   дистанция от МКАД (для городов МО), метро/шоссе/улицы, уникальные
   контент-поля (title, description, lead, included-фичи, FAQ).
2. **6 файлов данных** — по одному на направление (ВАО, ЮАО, ЮВАО, МО-восток,
   МО-юго-восток, МО-юг): массивы локаций + хаб-конфиг направления.
   НЕ один файл на страницу (74 файла немасштабируемо).
3. **`src/config/geo/index.ts`** — композер `composeGeoPage(loc)`:
   уникальные данные локации + общие блоки (шаги, базовые included, базовые FAQ)
   → `ServicePageConfig[]`. Экспорты: `geoPages`, `geoHubs`, `getGeoPage`,
   объединённый реестр `landingPages = [...servicePages, ...geoPages]`.
4. **Расширение `ServicePageConfig`** (обратимо-совместимые опциональные поля):
   - `relatedTitle?: string` — заголовок блока перелинковки (для хабов:
     «Районы, куда приезжаем»);
   - `parent?: { name: string; slug: string }` — уровень хлебных крошек
     (Главная → Хаб → Локация);
   - `areaName?: string` — конкретная гео-зона в `servicePageLd → areaServed`.
5. **Роут и sitemap** переключаются на `landingPages` (объединённый реестр);
   гео-страницы priority 0.7, хабы 0.8.
6. **Перелинковка:** хаб → все локации направления; локация → хаб +
   1–2 соседние локации + 1–2 услуги (related ≤3 для локаций, без лимита для хабов).

### Анти-дорвей гарантии (критично для Яндекса)

- Уникальные title / description / H1 / лид-абзацы / вопросы FAQ —
  Set-уникальность проверяется автотестами по всем ~81 страницам.
- ≥350 слов на страницу: уникальные лиды и FAQ + общие блоки.
- Реальные локальные факты в каждой странице: шоссе, улицы, метро, ориентиры,
  время подачи направления.
- Слаги — транслитерация по схеме проекта (vidnoe, tehniki): `evakuator-marino`,
  `evakuator-lyubercy`, `evakuator-chertanovo-yuzhnoe`.

## Альтернативы

### Вариант А: Data-driven модуль поверх ServicePage — ВЫБРАН
- **Плюсы:** переиспользование шаблона/роута/sitemap/JSON-LD; один формат
  конфига; массовая валидация тестами; добавление локации = запись в массив.
- **Минусы:** нужна дисциплина уникальности контента — закрывается тестами.
- **Оценка:** 9/10

### Вариант Б: 74 отдельных конфиг-файла (как vidnoe.ts)
- **Плюсы:** соответствие текущему паттерну «1 страница = 1 файл».
- **Минусы:** 74 файла по ~100 строк; реестр на 74 импорта; дублирование
  общих блоков в каждом файле; тяжёлая поддержка.
- **Оценка:** 4/10

### Вариант В: Контент в БД + админка
- **Плюсы:** редактирование без релиза.
- **Минусы:** противоречит ARCHITECTURE.md §4 (контент в git, без админки);
  SSG из БД усложняет сборку; усилие не оправдано для статичного контента.
- **Оценка:** 3/10

### Вариант Г: Вложенные URL (/geo/moskva/yuvao/marino)
- **Плюсы:** явная иерархия в URL.
- **Минусы:** ломает консистентность плоских слагов; хлебные крошки +
  перелинковка дают ту же семантику для Яндекса без смены паттерна.
- **Оценка:** 5/10

## Влияние на архитектуру

- Новые: `src/config/geo/` (types + 6 данных + index + тесты).
- Правки: `types/service-page.ts`, `ServicePage.tsx` (relatedTitle, parent),
  `lib/seo/json-ld.ts` (areaName), `app/(services)/[slug]/page.tsx` и
  `app/sitemap.ts` (объединённый реестр), `sitemap.test.ts`.
- Без изменений: БД, API, формы, дизайн-система.

## Риски и митигация

| Риск | Митигация |
|---|---|
| Фильтр Яндекса «качество» за массовые похожие страницы | Уникальные лиды/FAQ/меты (тесты), локальные факты, релевантная перелинковка, постепенный рост позиций |
| Каннибализация запросов (район vs округ) | Разные интенты: хаб = «эвакуатор ювao», район = «эвакуатор марьино»; уникальные меты |
| Устаревание локальных фактов | Данные в git, правка = коммит; дата lastModified в sitemap |
| Объём: ~81 страница в одном релизе | Все страницы статичны (SSG), тесты валидируют весь реестр автоматически |

## Критерии успеха

- [ ] ~81 новая гео-страница (41 район + ~27 городов + 6 хабов + exists Видное) в sitemap
- [ ] Все гео-страницы открываются (SSG), меты уникальны, H1 один на страницу
- [ ] Хлебные крошки: Главная → Хаб → Локация; JSON-LD Service + FAQPage на каждой
- [ ] `npm run test && npm run lint && npx tsc --noEmit` — зелёные
