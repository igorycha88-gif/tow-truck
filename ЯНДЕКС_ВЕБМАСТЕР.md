# Подробная инструкция: настройка Яндекс.Вебмастера

> Проект «Эвакуация Москва и МО», домен `эвакуация.online`.
> Техническая SEO уже реализована в коде (см. `SEO_SETUP.md`).
> Здесь — пошаговая настройка **внешнего** кабинета Яндекс.Вебмастера.

---

## Что даёт Вебмастер

- Индексация и ранжирование в Яндекс.Поиске
- Указание региона (Москва + МО) — **критично для локального SEO**
- Загрузка `sitemap.xml`, мониторинг обхода
- Главное зеркало (избавление от дублей `www`/`без www`, `http`/`https`)
- Сведения об организации (связь с Яндекс.Бизнесом → карта+поиск)
- Диагностика ошибок (микроразметка, титлы, 404, заражение)
- Переобход страниц по требованию

---

## Предварительные требования

| Условие | Статус проекта | Что проверить |
|---|---|---|
| Домен делегирован | ⏳ проверить | [webmaster.yandex.ru](https://webmaster.yandex.ru) → сайт должен резолвиться |
| A-запись домена → VPS | ⏳ проверить | `dig эвакуация.online` должен вернуть `178.57.218.204` |
| HTTPS работает | ✅ настроен | `curl -I https://эвакуация.online` → 200 + сертификат |
| `robots.txt` отдаётся | ✅ | https://эвакуация.online/robots.txt |
| `sitemap.xml` отдаётся | ✅ | https://эвакуация.online/sitemap.xml |
| Микроразметка schema.org | ✅ | `LocalBusiness`, `Organization`, `Service`, `FAQPage` |

> Если DNS не делегирован — Вебмастер не сможет проверить сайт. Сначала настройте A-запись у регистратора домена (TTL до 24 ч).

## Шаг 1. Вход и добавление сайта

1. Откройте [webmaster.yandex.ru](https://webmaster.yandex.ru).
2. Войдите под Яндекс-ID (желательно тот же, что и для Яндекс.Метрики и Яндекс.Бизнеса — они будут связаны).
3. Нажмите **«Добавить сайт»**.
4. Введите: **`https://эвакуация.online`** (с `https://`, без `www`, без слеша в конце).
5. Нажмите **«Добавить»** → откроется окно проверки прав.

---

## Шаг 2. Подтверждение прав на сайт

Яндекс предложит 3 способа. **Рекомендуемый для нашего проекта — «HTML-тег»** (код уже это поддерживает через ENV).

### Способ A. HTML-тег (рекомендуемый, уже поддерживается кодом)

1. В окне проверки выберите **«HTML-тег»**.
2. Яндекс покажет строку вида:
   ```
   <meta name="yandex-verification" content="a1b2c3d4e5f6g7h8" />
   ```
3. Скопируйте **ТОЛЬКО значение** атрибута `content` (например, `a1b2c3d4e5f6g7h8`).
4. На VPS откройте `.env`:
   ```bash
   ssh root@178.57.218.204
   nano /root/tow-truck/.env
   ```
5. Добавьте/замените строку:
   ```env
   NEXT_PUBLIC_YANDEX_VERIFICATION="a1b2c3d4e5f6g7h8"
   ```
6. ⚠️ **Важно:** `NEXT_PUBLIC_*` в Next.js инлайнятся при сборке. Просто перезапуск контейнера НЕ применит изменение — нужна пересборка образа. Два варианта:
   - **Простой:** сделать пустой коммит + `git push origin main` → авто-деплой пересоберёт образ.
     ```bash
     git commit --allow-empty -m "chore: rebuild with Yandex verification"
     git push origin main
     ```
   - **Вручную на VPS:** пересобрать образ из Dockerfile с build-arg (если есть локально) — сложнее, лучше через CI.
7. Дождитесь авто-деплоя (GitHub Actions: ~5 минут, см. вкладка Actions).
8. Проверьте, что тег появился:
   ```bash
   curl -s https://эвакуация.online/ | grep yandex-verification
   ```
   Должна выйти строка с вашим `content="..."`.
9. В Вебмастере нажмите **«Проверить»** → статус сменится на **«Права подтверждены»**.

### Способ B. DNS-запись TXT (если не хочется пересобирать образ)

1. В окне проверки выберите **«DNS»** → **«TXT-запись»**.
2. Яндекс даст значение вида: `yandex-verification: a1b2c3d4e5f6g7h8`.
3. Зайдите в панель управления DNS вашего домена (у регистратора: RU-CENTER, Reg.ru, Яндeddex.Коннект и т.п.).
4. Добавьте **TXT-запись**:
   - Имя (хост): `@` (или пусто)
   - Значение: `yandex-verification: a1b2c3d4e5f6g7h8`
   - TTL: по умолчанию
5. Дождитесь применения DNS (от 15 минут до нескольких часов).
   Проверка:
   ```bash
   dig TXT эвакуация.online +short
   ```
6. В Вебмастере нажмите **«Проверить»**.

> Способ B не требует правок кода/деплоя — удобно для первого подтверждения. Затем можно параллельно добавить и мета-тег (способ A) для надёжности.

### Способ C. Файл в корне (не наш случай)

Яндекс предлагает положить HTML-файл в корень сайта. В Next.js это `public/` — но способ менее удобен, чем A или B. Пропускаем.

### Способ D. Через Яндекс.Метрику (если счётчик уже на сайте)

Если на сайте уже установлен счётчик Метрики и он привязан к тому же Яндекс-ID → в Вебмастере можно подтвердить права в один клик через Метрику. Самый быстрый путь, если Метрика уже собирает данные.

## Шаг 3. Указание региона сайта (КРИТИЧНО)

Без региона сайт не показывается в локальной выдаче Яндекса («эвакуатор москва», «эвакуатор.MouseDown»). Это **самый важный шаг** для локального бизнеса.

1. В левом меню Вебмастера: **Настройки → Регион сайта** (или «Сведения о сайте → Регион»).
2. Нажмите **«Указать регион»**.
3. Добавьте ДВА региона:
   - **Москва** (город федерального значения)
   - **Московская область** (субъект РФ)
4. Подтвердите.

> Если Яндекс попросит подтверждение связи с реальным бизнесом — приложите ссылку на карточку в Яндекс.Бизнесе (см. `SEO_SETUP.md` Шаг 5) или скан учредительных документов.

Проверка: через 1–2 недели запросите в Яндексе «эвакуатор [район Москвы]» — сайт должен появляться в геозависимой выдаче.

## Шаг 4. Главное зеркало

Избавляет от дублей в индексе между `http://эвакуация.online` / `https://эвакуация.online` / `https://www.эвакуация.online`.

1. Левое меню: **Индексирование → Главное зеркало**.
2. Выберите: **`https://эвакуация.online`** (без `www`, с `https`).
3. Нажмите **«Сохранить»**.

> В nginx у нас уже настроен редирект www → без-www и http → https (`deploy/nginx/evakuaciya-online.conf`). Вебмастер это увидит автоматически через несколько дней, но явное указание ускоряет склейку.

---

## Шаг 5. Загрузка sitemap.xml

1. Левое меню: **Индексирование → Файлы Sitemap**.
2. Введите URL: **`https://эвакуация.online/sitemap.xml`**.
3. Нажмите **«Добавить»**.
4. Статус через несколько минут: **«Загружен»** + количество URL.

Ожидаемое содержимое (см. `src/app/sitemap.ts`):
```
https://эвакуация.online/
https://эвакуация.online/politika
```

> При добавлении новых страниц (услуги, зона покрытия) — они автоматически попадут в `sitemap.xml`, в Вебмастере пере-загружать не нужно (Яндекс пере-скачивает периодически).

---

## Шаг 6. Переобход главной страницы

Чтобы Яндекс быстрее индексировал новую версию сайта:

1. Левое меню: **Индексирование → Переобход страниц**.
2. Введите: **`https://эвакуация.online/`**.
3. (Опц.) В поле «Сообщить роботу новые URL» добавьте:
   ```
   https://эвакуация.online/
   https://эвакуация.online/sitemap.xml
   https://эвакуация.online/robots.txt
   ```
4. Отправьте. Робот придёт в течение 1–14 дней.

> После крупных изменений (новые страницы, тексты) — повторяйте этот шаг для каждой важной страницы.

---

## Шаг 7. Сведения об организации

Связывает сайт с карточкой организации в Яндекс.Бизнесе (карта + поиск). Даёт расширенный сниппет с адресом/телефоном/часами.

1. Левое меню: **Сведения о сайте → Организация** (или «Информация о сайте → Организация»).
2. Найдите вашу карточку в Яндекс.Бизнесе (если добавили — см. `SEO_SETUP.md` Шаг 5).
3. Привяжите её к сайту.
4. Если карточки нет — создайте прямо отсюда (заполните: название «Эвакуация Москва и МО», категория «Эвакуация автомобилей», телефон, адрес, часы 24/7, фото).

> Это самый мощный источник локального трафика для услуг эвакуации. Не пропускайте.

## Шаг 8. Исключение параметров URL

Чтобы URL с UTM-метками и другими параметрами не создавали дубли в индексе:

1. Левое меню: **Индексирование → Исключение параметров** (или «Параметры URL»).
2. Добавьте параметры для исключения:
   ```
   utm_source
   utm_medium
   utm_campaign
   utm_content
   utm_term
   utm_referrer
   yclid
   gclid
   fbclid
   from
   ```
3. Сохраните.

> У нас уже проставляются `<link rel="canonical">` на все страницы — это основной механизм против дублей. Исключение параметров — дополнительная подстраховка для Яндекса.

## Шаг 9. Диагностика и мониторинг ошибок

После индексации (через 1–2 недели) проверьте раздел **«Диагностика»**:

| Раздел | Что смотреть | Действие при ошибке |
|---|---|---|
| **Индексирование → Страницы в поиске** | сколько страниц в индексе | если 0 — проверить `robots.txt`, санкции |
| **Диагностика → Критические ошибки** | заражение, блокировка robots | исправить сразу |
| **Диагностика → Некритические ошибки** | тайтлы, описания, картинки | постепенно править |
| **Информация о сайте → Микроразметка** | schema.org: `LocalBusiness`, `FAQ`, `Service` | если есть ошибки — [validator.schema.org](https://validator.schema.org) |
| **Индексирование → Оригинальные тексты** | уникальность текстов | перед публикацией услуг/блога — добавлять сюда тексты заранее |
| **Трафик → Поисковые запросы** | по каким запросам показы/клики | расширять тексты под эффективные запросы |
| **Безопасность → Вирусы и малварь** | если взломают | мониторить |

### Частые ошибки и решения

- **«Документ запрещён в robots.txt»** — проверьте `robots.txt`, для `/politika` это нормально (noindex).
- **«Заголовок Last-Modified не возвращается»** — не критично, Next.js отдаёт `ETag`.
- **«Не указан регион»** → выполните Шаг 3.
- **«Сайт не подходит по региону запроса»** → добавьте тексты с гео-маркерами («эвакуатор Москва», «МКАД», «шоссе»).
- **«Микроразметка невалидна»** → проверить в [validator.schema.org](https://validator.schema.org) и «Инструмент проверки микроразметки» Яндекса.

## Шаг 10. Оригинальные тексты (опционально, но важно)

Перед публикацией новых текстов (услуги, статьи, FAQ — у нас уже есть) — добавьте их в **«Оригинальные тексты»**:

1. Левое меню: **Информация о сайте → Оригинальные тексты**.
2. Вставьте текст (от 500 символов), нажмите «Добавить».
3. В течение суток Яндекс зафиксирует авторство.

Для нашего проекта стоит добавить тексты:
- Ответы из FAQ (`src/config/faq.ts`) — это ценный текстовый контент.
- Текст Hero («Эвакуатор 24/7 в Москве и области…»).
- Описания услуг из `src/config/services.ts`.

## Шаг 11. Дополнительно (опционально)

- **Турбо-страницы** — ускоренные версии страниц для мобильных. Для лендинга эвакуации не критично (сайт и так быстрый), можно пропустить.
- **E-commerce** — не наш случай (услуги, не товары).
- **Лента RSS** — для блога/новостей, пока нет.
- **Связь с Яндекс.Метрикой** — в настройках счётчика Метрики убедитесь, что стоит галка «Вебмастер» (раздел «Интеграции»).

## Быстрая шпаргалка по ENV

После прохождения шагов 1–3 в `/root/tow-truck/.env` должно быть:

```env
NEXT_PUBLIC_SITE_URL="https://эвакуация.online"
NEXT_PUBLIC_YANDEX_VERIFICATION="<content из мета-тега>"
NEXT_PUBLIC_GOOGLE_VERIFICATION="<из Google Search Console>"
NEXT_PUBLIC_METRIKA_ID="<номер счётчика Метрики>"
NEXT_PUBLIC_LATITUDE="<широта вашей базы>"
NEXT_PUBLIC_LONGITUDE="<долгота вашей базы>"
NEXT_PUBLIC_YANDEX_MAPS_URL="<ссылка на карточку Яндекс.Бизнеса>"
```

После изменения **любой** `NEXT_PUBLIC_*` переменной — пересоберите образ:
```bash
git commit --allow-empty -m "chore: rebuild with updated NEXT_PUBLIC env"
git push origin main
```
Дождитесь авто-деплоя в GitHub Actions (~5 минут), проверьте через `curl`.

## Что Вебмастер НЕ делает (важно)

- **Не повышает позиции напрямую** — только сообщает о проблемах и помогает индексации.
- **Не заменяет контент** — тексты услуг/районов/блога дадут основной рост.
- **Не показывает данные в реальном времени** — данные обновляются с задержкой 1–7 дней.
- **Не связан с Google Search Console** — это два независимых кабинета, настраиваются отдельно (см. `SEO_SETUP.md` Шаг 4).
