## 1. Специфика ниши и требования к сайту

Сайт услуг эвакуации — это **service/lead-gen сайт с жёсткими требованиями**,
кардинально отличными от типового лендинга. Клиент приходит в состоянии стресса
(сломался на дороге, попал в ДТП), часто с мобильного, в зоне неуверенного приёма.

### Ключевые нефункциональные требования

| Требование | Целевое значение | Обоснование |
|------------|------------------|-------------|
| **LCP** (Largest Contentful Paint) | < 2.0 сек | Клиент на обочине, плохая связь, каждые 0.5с = потеря лида |
| **CLS** (Cumulative Layout Shift) | < 0.1 | Дёргающаяся страница раздражает в стрессе |
| **TBT** / client JS | минимальный | Сотовый 3G/4G в области — тяжёлый бандл = отказ |
| **Мобильный трафик** | mobile-first | 80%+ заходят с телефона, много — с дороги |
| **Доступность телефона** | sticky + floating | Телефон = главная конверсия, должен быть виден ВСЕГДА |
| **Аптайм** | 99.9% | 24/7 сервис, простой = потеря заказа |
| **SEO (локальное)** | топ Yandex/Google | Конкурентная ниша, трафик = «эвакуатор + район/шоссе» |
| **Отказоустойчивость заявок** | дублирование | Заявка = деньги; Telegram + БД как страховка |

### Воронка конверсии (приоритет CTA)

```
1. ПОЗВОНИТЬ          ← главная, sticky-header + floating-btn (крупно, контрастно)
2. Заказать звонок     ← форма (телефон + локация), отправка → Telegram
3. WhatsApp / Telegram ← deep-links (мессенджеры популярны в РФ)
4. Онлайн-калькулятор  ← вовлечение + захват лида (расчёт → заявка)
```

## 2. Лучшие практики сайтов эвакуации (конкурентный анализ)

### 2.1 Контентные блоки главной (must-have)

1. **Hero** — УТП + телефон + кнопка заявки + «подача 15–30 мин / 24/7»
2. **Услуги** — эвакуация легковых / мото / спецтехники / внедорожников / после ДТП / запуск двигателя / подвоз топлива
3. **Калькулятор** — расчёт стоимости (тип авто, расстояние, время суток)
4. **Зона покрытия** — карта Москвы + МО, список шоссе/районов/км МКАД
5. **Цены** — прайс «от X ₽» по типам услуг (прозрачность = доверие)
6. **Преимущества** — 24/7, своя техника, лицензии, опыт, отзывов N
7. **Отзывы** — реальные с фото/именами (не сток)
8. **Схема работы** — 1→2→3→4 (звонок → подача → погрузка → оплата)
9. **FAQ** — подграф под SEO long-tail («сколько стоит эвакуатор до...»)
10. **Форма заявки** — minimal: телефон + адрес/локация
11. **Контакты** — телефоны, мессенджеры, юр. лицо, реквизиты

### 2.2 SEO-стратегия (критично)

- **Local SEO**: посадочные под локации — `эвакуатор [район/шоссе/город МО]`
- **Schema.org**: `LocalBusiness` + `Service` + `AggregateRating` + `Offer`
- **Yandex.Webmaster** + **Yandex.Метрика** (основной трафик — Яндекс в РФ)
- **Open Graph** + Twitter Cards
- `sitemap.xml` (next-sitemap) + `robots.txt`
- Чистые URL, серверный рендеринг (App Router Server Components)
- Микроразметка FAQ
- Core Web Vitals → высокие позиции

### 2.3 Доверие и конверсия

- Реальные фото техники и водителей (не сток)
- «Подача 15–30 минут» конкретно
- Чёткий прайс «от»
- Отзывы с именами/датами
- Юр. реквизиты, ИНН — легальность
- 24/7 + мгновенный ответ (Telegram-бот оператору)

### 2.4 Производительность

- **Server Components** по умолчанию (минимум client JS)
- `next/image` + WebP/AVIF для фото техники
- Static Generation для контентных страниц (услуги, районы)
- Сервис-воркер не нужен (усложняет), но кэш Nginx + CDN
- Шрифты: `next/font` с оптимизацией

### 2.5 Соответствие законодательству РФ

- **152-ФЗ** — согласие на обработку ПД в форме заявки (чекбокс + ссылка на политику)
- Политика конфиденциальности
- Соглашение на обработку cookie (при использовании Метрики)

## 3. Выбранный технический стек

### Frontend

| Слой | Технология | Версия | Обоснование |
|------|------------|--------|-------------|
| Фреймворк | **Next.js** (App Router) | 15.x | SSR/SSG + RSC = лучший SEO + минимум client JS |
| UI runtime | **React** | 19.x | Server Components, use() API |
| Язык | **TypeScript** | 5.5+ strict | Типобезопасность, меньше багов |
| Стили | **Tailwind CSS** | 3.4 | Utility-first, быстрый, консистентный дизайн |
| UI-кит | **shadcn/ui** + Radix UI | latest | Доступные, кастомные компоненты без vendor lock-in |
| Иконки | **lucide-react** | latest | Tree-shakeable, современные |
| Формы | **React Hook Form** + **Zod** | latest | Производительность + типобезопасная валидация |
| Карта | **Yandex Maps JS API** | 3.0 | Лучшее покрытие Москвы/МО, РФ-локальный |
| Валидация телефона | **libphonenumber-js** | latest | Корректный формат RU (+7) |

### Backend (в рамках Next.js)

| Слой | Технология | Версия | Обоснование |
|------|------------|--------|-------------|
| API | **Next.js Route Handlers** | — | Единый кодбейс, Server Actions / Routes |
| БД | **PostgreSQL** | 16 | Хранение заявок (долговечная запись), каталога услуг/цен/отзывов |
| ORM | **Prisma** | 5.x | Типобезопасный доступ к БД |
| Кэш / Rate-limit | **Redis** | 7 | Антиспам формы, сессии, троттлинг |
| Уведомления | **Telegraf** (Telegram Bot API) | latest | Мгновенная доставка заявок оператору |
| Email (резерв) | **Nodemailer** | latest | Фолбэк-канал уведомлений |
| Логирование | **pino** | latest | Структурированные логи, быстрые |

### Тестирование

| Слой | Технология | Обоснование |
|------|------------|-------------|
| Unit / Integration | **Vitest** | Современный, быстрый, ESM-native (пришёл на смену Jest) |
| E2E | **Playwright** | Кроссбраузерный, надёжный, мокби-адаптив |
| Покрытие | **c8** (через Vitest) | Минимум 60% для новых файлов |

### Инфраструктура и деплой

| Слой | Технология | Обоснование |
|------|------------|-------------|

## 5. Модель данных (кратко, детализирует Архитектор)

Основные сущности (без админки — каталог услуг/цен/отзывов ведётся через `src/config/` + seed):

- **Order** — заявка (phone, name?, location, serviceType, vehicleType, status, source, createdAt, utm?)
- **Service** — услуга (slug, title, description, basePrice, icon) — *seed/config*
- **Review** — отзыв (author, text, rating, photo?, date) — *seed/config*
- **ServiceArea** — зона покрытия (district, highway?, basePriceModifier) — *config*

> Решение: контент (услуги/цены/отзывы) — в **TypeScript-конфигах** (`src/config/`),
> т.к. админки нет. Заявки — в PostgreSQL для долговечности и аналитики.
> Резервно дублируются в Telegram оператору.

## 8. Принятые компромиссы

1. **PostgreSQL + Redis вместо чистой статики** — добавляют сложность, но дают
   долговечное хранение заявок (страховка от сбоев Telegram) и антиспам. Оправдано.
2. **Vitest вместо Jest** — современнее и быстрее, но команда должна знать разницу
   в конфигурации. Принято ради актуальности стека.
3. **Контент в TS-конфигах, а не в БД** — нет админки, но управление через git +
   seed проще и прозрачно. При росте — можно вынести в БД + админку.
4. **Yandex Maps вместо Google Maps** — лучше покрытие РФ, не блокируется,
   привычнее для аудитории.
