## 1. Суть

Сайт эвакуация.online расширяет выгрузку бизнес-метрик в существующий эндпоинт
`GET https://эвакуация.online/metrics/tracking` (Prometheus text, защита
`X-Monitoring-Key`, интервал скрейпа ~60 с — всё без изменений).

**Со стороны мониторинга конфигурация НЕ меняется**: Prometheus подхватит
актуальный состав `business_*`-метрик автоматически. Требуется обновить
панели на дашборде «Бизнес сайта» (или в отдельном ряду «Путь клиента»):
добавить новые (§3) и удалить устаревшие (§4).

## 4. Удалить со стороны мониторинга (v1.1)

На дашборде «Бизнес сайта» убрать панели, если были созданы по v1.0:

- «Заявки» / «Лиды» — все панели на `business_leads_*`;
- «Конверсия» — все панели на `business_conversion_rate_*`;
- «WhatsApp-клики» — все панели на `business_whatsapp_*`;
- серия «Заявки» из смешанных графиков (например, «Трафик и лиды») и
  стадию `lead` из воронок (метрика больше не отдаёт эту серию — панель
  просто начнёт показывать 3 стадии автоматически).

## 5. Ограничения и заметки

- Метрики `_24h/_7d` — гейджи-окна, пересчитываются сайтом раз в 60 с; история
  строится временным рядом Grafana (как у текущих `business_*`).
- `business_phone_clicks_event` — семплы `1 <unix_ms>`; Prometheus отбрасывает
  семплы с timestamp старше ~10 мин, поэтому **график кликов строить на
  window-гейджах** `business_phone_clicks_12h` / `_7d` (не на `*_event`).
  `*_event` пригоден только для `count_over_time` короткого окна.
- Метрики телефона рендерятся только при наличии кликов за окно (нет кликов —
  метрика отсутствует, это норма, не ошибка скрейпа).
- Алерты: можно добавить `SiteNoTraffic`-расширение
  (`business_sessions_24h == 0`) — по желанию, не обязательно.

## 6. Критерии приёмки (со стороны мониторинга)

- Метрики §2 присутствуют в Prometheus после выкатки сайта
  (`monitoring_site_metrics_up{site="эвакуация.online",kind="tracking"}=1` сохраняется).
- **Удалённые метрики отсутствуют**: `business_leads_*`,
  `business_conversion_rate_*`, `business_whatsapp_*` не возвращаются
  `/metrics/tracking` и не нужны на дашбордах.
- Панели §3 отображают данные (после накопления трафика); воронка — 3 стадии.
- Панели §4 убраны с дашборда «Бизнес сайта».
- Новых алертов/ошибок скрейпа нет.

## 7. Что НЕ требуется

- Изменений `config/sites.yml`, ключей, интервалов, эндпоинтов, портов — нет.
- Доступ к БД сайта — не нужен (как и раньше, только `/metrics/*`).
- Удаление исторических данных — не требуется (в Prometheus старые серии
  `business_leads_*` / `business_whatsapp_*` устареют сами по retention).
