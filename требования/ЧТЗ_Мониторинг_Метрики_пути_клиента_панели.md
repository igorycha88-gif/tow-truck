## 1. Суть

Сайт эвакуация.online расширяет выгрузку бизнес-метрик в существующий эндпоинт
`GET https://эвакуация.online/metrics/tracking` (Prometheus text, защита
`X-Monitoring-Key`, интервал скрейпа ~60 с — всё без изменений).

**Со стороны мониторинга конфигурация НЕ меняется**: Prometheus подхватит новые
`business_*`-метрики автоматически. Требуется только добавить панели на дашборд
«Бизнес сайта» (или создать отдельный ряд «Путь клиента»).

## 2. Новые метрики (полный список)

### 2.1 Ключевые гейджи — добавлены парные окна 7д

`business_sessions_7d`, `business_page_views_7d`, `business_unique_visitors_7d`,
`business_avg_session_duration_seconds_7d`, `business_bounce_rate_7d`,
`business_leads_7d`, `business_conversion_rate_7d`, `business_phone_clicks_7d`.

### 2.2 Новые метрики пути клиента

| Метрика | Лейблы | Смысл |
|---|---|---|
| `business_landing_pages_24h` / `_7d` | `page` | страницы входа (топ-10 + other) |
| `business_page_transitions_24h` / `_7d` | `from`, `to` | переходы внутри сайта (топ-10 пар) |
| `business_entry_flows_24h` | `source`, `landing` | источник трафика × посадочная страница |
| `business_exit_pages_24h` / `_7d` | `page` | страницы выхода (где теряем) |
| `business_funnel_24h` / `_7d` | `stage` = visit, content_view, contact_click, lead | воронка |
| `business_avg_pages_per_session_24h` / `_7d` | — | глубина просмотра |
| `business_avg_time_on_page_24h` / `_7d` | — | среднее время на странице, сек |
| `business_top_dwell_pages_24h` | `page` | топ-5 страниц по времени на странице |

### 2.3 Дополнительные разрезы

| Метрика | Лейблы | Смысл |
|---|---|---|
| `business_devices_24h` / `_7d` | `device` = mobile, tablet, desktop | устройства |
| `business_visitors_returning_24h` / `_7d` | — | вернувшиеся посетители |
| `business_whatsapp_clicks_12h` / `_7d` | — | клики по кнопкам WhatsApp |
| `business_whatsapp_clicks_event` | — | события кликов WhatsApp с точным timestamp (24ч, паттерн `business_phone_clicks_event`) |

Все срезы — топ-N + `other`, суммарно ≤ 20 значений лейбла на метрику
(кардинальность контролирует сайт).

## 3. Рекомендуемые панели

| # | Панель | Тип | Запрос (пример) |
|---|---|---|---|
| 1 | Воронка 24ч / 7д | Bar gauge | `business_funnel_24h` (sort by stage) |
| 2 | Страницы входа | Bar gauge | `business_landing_pages_24h` |
| 3 | Переходы между страницами | Table | `business_page_transitions_24h` |
| 4 | Источник → посадочная | Table | `business_entry_flows_24h` |
| 5 | Устройства | Pie | `business_devices_24h` |
| 6 | Клики: телефон vs WhatsApp | Time series | `business_phone_clicks_event`, `business_whatsapp_clicks_event` |
| 7 | Время на странице / глубина | Stat | `business_avg_time_on_page_24h`, `business_avg_pages_per_session_24h` |
| 8 | Вернувшиеся посетители | Stat | `business_visitors_returning_24h` |

## 4. Ограничения и заметки

- Метрики `_24h/_7d` — гейджи-окна, пересчитываются сайтом раз в 60 с; история
  строится временным рядом Grafana (как у текущих `business_*`).
- `*_event`-метрики — семплы `1 <unix_ms>`; считать через `count_over_time`.
- Алерты: можно добавить `SiteNoTraffic`-расширение
  (`business_sessions_24h == 0`) — по желанию, не обязательно.

## 5. Критерии приёмки (со стороны мониторинга)

- Все метрики §2 присутствуют в Prometheus после выкатки сайта
  (`monitoring_site_metrics_up{site="эвакуация.online",kind="tracking"}=1` сохраняется).
- Панели §3 отображают данные (после накопления трафика).
- Новых алертов/ошибок скрейпа нет.

## 6. Что НЕ требуется

- Изменений `config/sites.yml`, ключей, интервалов, эндпоинтов, портов — нет.
- Доступ к БД сайта — не нужен (как и раньше, только `/metrics/*`).
