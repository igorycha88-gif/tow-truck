> **Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps
> **Исполнитель:** Разработчик (fullstack) + контент-редактор
> **Версия ЧТЗ:** 1.0
> **Дата:** 2026-08-24
> **Приоритет:** High
> **Статус:** Draft
> **Основание:** Анализ данных Яндекс.Вебмастера за 23.07–23.08.2026 (БД мониторинга, webmaster.db)

---

## 1. Резюме

Сайт начал ранжироваться в Яндексе ~16.08.2026 (первый ненулевой показ). За неделю
показы выросли с 85 до 140/нед, в выдаче 50 запросов, из них 30 на стр. 1 (позиции 1–10).
Однако **кликов — 0 при 140 показах**, а ~36% запросов — мусорные (нонсенс-фразы,
телефоны, бренд конкурента). Сайт состоит из ОДНОЙ посадочной страницы — все запросы
конкурируют за главный документ, длинный хвост не закрыт.

**Три ключевые проблемы:**

| # | Проблема | Данные | Последствие |
|---|----------|--------|-------------|
| P1 | CTR = 0% при позициях 4–10 | 140 показов/нед, 0 кликов; норма CTR на поз. 5–10 — 2–5% | Потеря всего органического трафика |
| P2 | Нет посадочных под кластеры запросов | 1 страница (`/`) + `/politika`; запросы «после аварии» (поз. 15), «с лебедкой» (10.5), «мото» (7) не имеют релевантных URL | Потолок позиций 8–15, нет роста |
| P3 | Мусорные запросы ~36% | 18 из 50 запросов — word-salad («…перевести корпус связей в нейтральное»), телефоны, «свободный-эвакуатор рф» | Размытие релевантности, риск фильтра за переспам/низкокачественный контент |

## 4. Функциональные требования

### ЭПИК-1. Оптимизация сниппетов и CTR (закрывает P1) — Приоритет: Critical

**1.1. Title главной страницы** — текущий шаблон `${title} — ${siteConfig.name}`
не содержит телефона, цены и триггеров клика. Требования к новому title главной:

- [ ] Формат (≤ 60 символов до обрезки): `[УТП] + [гео] + [ценовой триггер]`
- [ ] Пример эталона: `Эвакуатор 24/7 Москва и МО — подача 15–30 мин, от 2 500 ₽`
- [ ] Главный ключ «эвакуатор 24/7» — в первых 30 символах
- [ ] Телефон в title НЕ добавлять (в Яндексе телефон в сниппете берётся из
      Яндекс.Бизнеса/справочника — см. ЭПИК-6)

**1.2. Description главной:**

- [ ] ≤ 160 символов, содержит: круглосуточно 24/7, подача 15–30 мин, фиксированная
      цена, «своя техника», призыв «Звоните сейчас»
- [ ] Цену брать из актуального источника цен (синхронизировать с ЧТЗ_Обновление_цен,
      не хардкодить в двух местах — вынести в `src/config/pricing.ts` или источник цен)

**1.3. Мета-данные новых страниц (см. ЭПИК-2)** — уникальные title/description
на каждую страницу по шаблонам из Таблицы 4.1.

**1.4. Быстрые ссылки (sitelinks) Яндекса:**

- [ ] Навигация и заголовки секций дают понятные якоря: «Услуги», «Цены», «Как работаем»,
      «Контакты» — проверить, что `<nav>` ссылки на `/#services`, `/#prices` (если секции нет —
      добавить якорь) текстово совпадают с желаемыми быстрыми ссылками
- [ ] В Яндекс.Вебмастере (вручную, инструкция в SEO_SETUP.md) подать желаемые быстрые ссылки

**1.5. Проверка сниппетов:**

- [ ] Скриншоты сниппетов главной и всех новых страниц из «Проверки страницы» Вебмастера
      приложить к PR (в `требования/` или в описании PR)

- [ ] Страница 404 для несуществующих слагов, редиректов старых URL нет (новые страницы)

## 5. Нефункциональные требования

- **Производительность:** новые страницы — SSG (`generateStaticParams`), LCP ≤ 2.5 c
  на мобильных (проверка Lighthouse в CI или вручную в PR)
- **Качество текстов:** обязательная человеческая вычитка каждого текста;
  forbidden-словарь word-salad фраз из раздела 3.4 в тесте (см. TASK-TST)
- **Типизация:** строгий TS (`npm run typecheck`), все конфиги страниц — через
  интерфейс `ServicePageConfig`
- **Единый источник цен:** цена упоминается в мета и контенте из одного конфига —
  рассинхрон цен = баг
- **Безопасность:** никаких ключей/токенов в коде новых страниц

## 10. Критерии приёмки (общие, проверяемые)

- [ ] `npm run build` успешно; все 7 страниц в SSG-выводе, в `sitemap.xml`
- [ ] Автотесты (`vitest`): метаданные уникальны у всех страниц, sitemap содержит все URL,
      forbidden-словарь word-salad не встречается в контенте, JSON-LD валиден,
      цены из единого источника совпадают в мета и контенте
- [ ] `grep` по запрещённым строкам (раздел ЭПИК-3) — пусто
- [ ] Lighthouse мобильный ≥ 85 (перфоманс) для главной и 2–3 случайных страниц
- [ ] Сниппеты проверены в «Проверке страницы» Вебмастера (скриншоты в PR)
- [ ] Все страницы отправлены на переобход после деплоя

## Маршрутизация

**Архитектор:** ТРЕБУЕТСЯ (свёрнуто) — новый шаблон страниц `(services)/[slug]`
меняет структуру App Router; решение зафиксировано в данном ЧТЗ (SSG + реестр конфигов),
отдельный ADR не нужен.

**Исполнитель:** Разработчик (fullstack) — TASK-SEO2-001..008;
контент-вычитка — человек (владелец/редактор) обязательна.

**DevOps:** стандартный деплой после GO от Тестировщика + переобход в Вебмастере.

**Обоснование:** задачи контент+код (мета, страницы, перелинковка, тесты) —
профиль Разработчика; внешние работы (ЭПИК-6) — инструкция для владельца.
