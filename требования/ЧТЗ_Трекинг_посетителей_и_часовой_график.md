## 0. Диагностика (почему посетители не отображаются)

Проверка БД (`tow_truck`, 2026-08-14):

| Факт | Значение |
|---|---|
| Заявок всего / с IP | 3 / 2 (последняя — 26 июля) |
| Кликов всего / уник. IP | 4 / 1 (последний — 10 августа) |
| Grafana-панель «Посетители» | `COUNT(DISTINCT ip)` **только из "Order"** за 1 день |
| Заявок за последние сутки | 0 → панель показывает 0 |

**Корневые причины:**
1. Панель «Посетители» считает IP только из заявок. Заявок нет → 0.
2. **Трекинга визитов не существует вообще.** Посетитель фиксируется только
   если оставил заявку или кликнул по номеру. Обычный просмотр сайта
   нигде не записывается → метрика «посетители» не отражает реальный трафик.
3. IP хранятся в IPv6-формате (`::ffff:172.217.18.170`) — на дедупликацию
   не влияет, но нормализуем для чистоты данных.

## 1. Цели и задачи

### 1.1 Бизнес-цель
Начать реально фиксировать каждое посещение сайта и видеть в Grafana,
в какие часы приходят посетители — для анализа пиков нагрузки и
эффективности рекламы.

### 1.2 Пользовательская ценность
Владелец открывает Grafana и видит: сколько посетителей было сегодня/за неделю
и почасовое распределение посещений (когда люди приходят).

### 1.3 Метрики успеха
- Каждый заход на сайт фиксируется в таблице `Visit`
- Панель «Посетители» показывает данные даже при 0 заявок и 0 кликов
- Часовой график отражает время посещений (по Москве)

---

## 2. Функциональные требования

### 2.1 User Stories с Acceptance Criteria

**US-001: Трекинг визита**
- GIVEN я открываю любую страницу сайта
- WHEN страница загружается в браузере
- THEN создаётся запись в `Visit` (ip, userAgent, page, createdAt)
- AND повторные загрузки в одной сессии браузера не дублируются (sessionStorage)

**US-002: Панель «Посетители» в Grafana**
- GIVEN за последние сутки были визиты, но 0 заявок и 0 кликов
- WHEN я открываю дашборд
- THEN панель «Посетители» показывает число уникальных IP из `Visit`

**US-003: Часовой график посещений**
- GIVEN есть визиты в разное время суток
- WHEN я смотрю панель «Посетители по часам» (диапазон 24-48ч)
- THEN вижу столбцы/bar по часам — сколько уникальных посетителей в каждый час
- AND время отображается по московскому часовому поясу (timezone: browser + UTC в БД корректно)

**US-004: Антиспам**
- GIVEN бот шлёт POST /api/visit чаще лимита
- WHEN превышен rate-limit
- THEN ответ 429 и запись не создаётся

## 3. Нефункциональные требования

### 3.1 Производительность
- Трекинг fire-and-forget: не блокирует рендер, без await на клиенте
- Beacon отправляется после загрузки страницы (useEffect), не влияет на LCP/CLS

### 3.2 Безопасность и 152-ФЗ
- Храним только: ip, userAgent, страницу, время. Без ПДн
- Rate-limit: `RATE_LIMIT_VISIT_PER_HOUR` (дефолт 120) с IP (Redis)
- Валидация Zod на входе

### 3.3 Данные
- IP нормализуется: `::ffff:1.2.3.4` → `1.2.3.4`

## 4. Техническая архитектура

### 4.1 Изменения в БД (новая модель)

```prisma
model Visit {
  id        String   @id @default(cuid())
  ip        String?
  userAgent String?
  page      String   @default("home")
  createdAt DateTime @default(now())

  @@index([createdAt])
  @@index([page])
}
```

Миграция: `npx prisma migrate dev --name add_visit` (dev) / `migrate deploy` (prod).

### 4.2 API

**POST /api/visit** — фиксация визита
```
Request:  { "page": "home" }
Response: 201 { "id": "..." }
Errors:   400 VALIDATION_ERROR / 429 RATE_LIMIT_EXCEEDED / 500 INTERNAL_ERROR
```
Zod: page — enum/строка 1-100 символов (по факту как click-event).

**GET /api/metrics** — visitors теперь считается из Visit (+ сохранён union
с Order/ClickEvent как «активность»). Обновить BusinessMetrics:
`visitors` = уникальные IP из Visit; Visit — источник истины.

### 4.3 Структура файлов
```
src/
├── app/api/visit/route.ts          # POST — трекинг визита
├── components/visit-tracker/
│   └── VisitTracker.tsx            # Client: beacon 1 раз/сессию
├── lib/validators/visit.ts         # Zod-схема
├── lib/utils.ts                    # normalizeIp() + getClientIp
├── services/metricsService.ts      # createVisit() + getMetrics из Visit
grafana/dashboards/business-metrics.json  # исправленная панель + часовой график
prisma/schema.prisma                # model Visit
```

### 4.4 Grafana-дашборд (правки)
1. Панель 3 «Посетители (сегодня)»: SQL →
   `COUNT(DISTINCT "ip") FROM "Visit" WHERE "createdAt" >= now() - interval '1 day' AND ip IS NOT NULL AND ip <> 'unknown'`
2. Новая панель «Посетители по часам» (timeseries, bars):
   ```sql
   SELECT date_trunc('hour', "createdAt") AS "Time",
          COUNT(DISTINCT "ip")::int AS "Посетители"
   FROM "Visit"
   WHERE $__timeFilter("createdAt") AND "ip" IS NOT NULL AND "ip" <> 'unknown'
   GROUP BY 1 ORDER BY 1;
   ```
   + вторая серия «Визиты» (COUNT(*)) для сравнения.
3. Timezone дашборда: browser (МСК у владельца) — корректно с UTC-инстантами.

### 4.5 Server vs Client
| Компонент | Тип | Причина |
|---|---|---|
| /api/visit | Server (Route Handler) | Запись в БД |
| VisitTracker | Client | Отправка beacon после загрузки |
| metricsService | Server | Prisma только в services |
