# ЧТЗ: Email-уведомления о заявках через Яндекс SMTP

**Дата:** 2026-08-31
**Маршрут:** 1 (Аналитик → Разработчик → Тестировщик → DevOps)
**Архитектор:** не требуется (нет новых сущностей БД / endpoints; Nodemailer уже в стеке)

## 1. Проблема

Сейчас email — только фолбэк при сбое Telegram и на один адрес (`NOTIFY_EMAIL`).
SMTP не настроен. Заявки не приходят на почту.

## 2. Цель

Каждая заявка с сайта отправляется на ПОЧТУ всегда (параллельно с Telegram)
через Яндекс SMTP.

## 3. Требования

### Функциональные

- FR-1. Email — самостоятельный параллельный канал: отправляется при КАЖДОЙ заявке,
  независимо от результата Telegram.
- FR-2. Получатели: `boronin87@list.ru` И `igorycha.s@yandex.ru` (обе письмом,
  список через запятую в `NOTIFY_EMAIL`).
- FR-3. SMTP-аккаунт Яндекса: `boronind1m@yandex.ru` (smtp.yandex.ru:465, SSL).
  Аутентификация — пароль приложения Яндекс.
- FR-4. Письмо: тема `Новая заявка на эвакуацию #<orderId>`, текст и HTML-версия
  с полями: Имя, Телефон, Адрес, Услуга, ID.
- FR-5. Сбой SMTP не роняет создание заявки (fire-and-forget, как сейчас).

### Нефункциональные

- NFR-1. Логирование: skip при ненастроенном SMTP, успех (с числом получателей),
  ошибки с контекстом orderId.
- NFR-2. `secure: true` для порта 465, STARTTLS для 587.
- NFR-3. Секреты только в `.env` (в git не попадают).

## 5. Критерии приёмки

- AC-1. Заявка → письмо на ОБЕ почты при настроенном SMTP.
- AC-2. Telegram выключен → письмо всё равно уходит.
- AC-3. SMTP не настроен → заявка создаётся, warning в логах, без падения.
- AC-4. `npm run test && npm run lint && npx tsc --noEmit` — зелёные.
- AC-5. Пошаговая инструкция по настройке Яндекс (2FA + пароль приложения) выдана пользователю.

## 6. Что делает пользователь (вне кода)

1. Включить 2FA на аккаунте boronind1m@yandex.ru.
2. Создать пароль приложения «Почтовые программы».
3. Вписать переменные в `.env` (значения выданы).
