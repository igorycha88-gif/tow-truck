# ЧТЗ: Читаемый номер заявки (дата + порядковый номер)

**Дата:** 2026-08-31
**Маршрут:** 2 (Аналитик → Архитектор → Аналитик → Разработчик → Тестировщик → DevOps)
**ADR:** ADR-013-Readable-Order-Number.md

## 1. Проблема

Номер заявки — cuid (`cmth2...`), нечитаем в письмах, Telegram и для клиента.

## 2. Цель

Читаемый номер `ГГГГММДД-N` (пример: `20260831-1`): дата подачи (Москва) + дефис +
порядковый номер. Счётчик сквозной: начинается с 1, до бесконечности, не сбрасывается.

## 3. Требования

- FR-1. БД: колонка `Order.number Int @unique @default(autoincrement())` (PG sequence).
  Существующим заявкам миграция проставляет номера 1..K.
- FR-2. Helper `formatOrderNumber(createdAt, number)` → `ГГГГММДД-N`, дата в Europe/Moscow.
- FR-3. Тема письма: `Новая заявка на эвакуацию №20260831-5`; номер в теле письма (text+html).
- FR-4. Telegram-текст: строка `Номер: №20260831-5`.
- FR-5. API POST /api/orders: в ответе 201 поле `number` (строка `ГГГГММДД-N`).
- FR-6. UI (OrderForm): в успехе показывать «Заявка №20260831-5 принята!».
- FR-7. Логирование: orderId + number в ключевых операциях.

## 4. Декомпозиция

- TASK-BCK-002: ordersService (select number, displayNumber) + тесты

- TASK-FRT-001: OrderForm — номер в сообщении успеха
- TASK-INF-001: `npx prisma migrate dev` (dev), `prisma generate`

## 5. Критерии приёмки

- AC-1. Новая заявка получает number = предыдущий + 1 (сквозной, без сброса по дате).
- AC-2. Тема письма содержит `№ГГГГММДД-N`; дата по Москве (UTC+3).
- AC-3. Существующие заявки пронумерованы 1..K, новые продолжаются с K+1.
- AC-4. UI показывает номер принятой заявки.
- AC-5. `npm run test && npm run lint && npx tsc --noEmit` — зелёные; покрытие новых файлов ≥ 60%.
- AC-6. Живой тест dev: POST заявки → письмо с номером на обе почты.

## 6. Риски

- Гонки — исключены (sequence атомарен).
- Миграция на прод — при следующем деплое (`migrate deploy`), существующие заявки пронумеруются.
