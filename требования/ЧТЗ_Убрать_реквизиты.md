# ЧТЗ: Убрать реквизиты компании с сайта

## Контекст
На сайте публично отображаются реквизиты компании — `legalName` («ИП Иванов И. И.»)
и `inn` («770000000000») — это заглушки. Пользователь просит убрать реквизиты с сайта.
Бренд «Эвакуация Москва и МО» и контакты (телефон, адрес, режим работы) остаются.

## Решение (маршрутизация)
Вариант: **«Полностью из UI»**.
- Убрать блок «Реквизиты» из футера и ИНН из секции «Контакты».
- Поля `legalName` и `inn` убрать из типа `CompanyInfo` и конфига `company`.
- Копирайт футера перевести на бренд (`company.name`).
- В политике конфиденциальности (152-ФЗ) оператора ПДн переформулировать на
  бренд + контакты (телефон), без ИНН/юр. названия.

**Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps (Маршрут 1, код-задача).
**Архитектор:** не требуется (нет изменений БД/API/архитектуры).

## Критерии приёмки
1. `legalName` и `ИНН` **не выводятся** нигде в UI (Footer, Contacts).
2. Блок «Реквизиты» в футере полностью удалён; копирайт использует `company.name`.
3. В секции «Контакты» больше нет строки с ИНН (сетка `sm:grid-cols-3` аккуратно
   перестроена — см. детали в декомпозиции, без визуальных «дыр»).
4. В политике конфиденциальности оператор ПДн указан как бренд
   (`Эвакуация Москва и МО`) + телефон; `legalName`/`ИНН` отсутствуют (152-ФЗ: оператор
   идентифицирован по наименованию и контакту).
5. Поля `legalName` и `inn` удалены из `CompanyInfo` и объекта `company` (больше не
   являются частью публичной конфигурации).
6. `npm run test && npm run lint && npx tsc --noEmit` — зелёные.
7. Автотесты обновлены: убрана проверка `company.inn`; добавлены проверки отсутствия
   реквизитов и корректности копирайта/политики.
8. Логирование не затрагивается (изменения чисто статические/SSR — нового
   логирования не требуется; существующее не ломается).
