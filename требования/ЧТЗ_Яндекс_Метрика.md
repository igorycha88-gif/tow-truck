# ЧТЗ: Подключение Яндекс.Метрики (ID 111456265)

**Дата:** 2026-08-10
**Маршрут:** Стандартный (Аналитик → Разработчик → Тестировщик → DevOps)
**Тип:** Малая задача (раздел 6 AGENTS.md) — 2 файла, без БД/API/архитектуры.

---

## 1. Постановка

Добавить на сайт счётчик Яндекс.Метрики с ID `111456265` по сниппету, предоставленному
пользователем. Настроить расширенные опции инициализации.

## 2. Текущее состояние

Метрика уже встроена в `src/app/layout.tsx` как stub, рендерящийся только при заданном
`NEXT_PUBLIC_METRIKA_ID`. Отличия от целевого сниппета:
- URL тега без `?id=` (нужно `https://mc.yandex.ru/metrika/tag.js?id=<ID>`).
- В `init` нет опций `ssr`, `ecommerce`, `referrer`, `url`.
- ID не задан: `NEXT_PUBLIC_METRIKA_ID` пуст в `docker-compose.dev.yml`.

## 3. Критерии приёмки

- [ ] Сниппет в `layout.tsx` соответствует целевому (URL с `?id=`, расширенный `init`).
- [ ] ID `111456265` подставляется из env-переменной `NEXT_PUBLIC_METRIKA_ID`
      (паттерн проекта сохранён — не хардкод).
- [ ] `<noscript>`-пиксель рендерится с тем же ID.
- [ ] `NEXT_PUBLIC_METRIKA_ID` задан в `docker-compose.dev.yml` = `111456265`.
- [ ] Автотест: рендер счётчика при заданном ID и отсутствие при пустом.
- [ ] `npm run test && npm run lint && npx tsc --noEmit` — зелёные.

## 4. Файлы для изменения

| Файл | Изменение |
|------|-----------|
| `src/app/layout.tsx` | Привести сниппет Метрики к целевому виду |
| `docker-compose.dev.yml` | `NEXT_PUBLIC_METRIKA_ID: '111456265'` |
| `src/app/layout.test.tsx` (новый) | Автотест рендера счётчика |

## 5. Декомпозиция

- **TASK-FRT-001:** Обновить сниппет Метрики в `layout.tsx`.

(см. `SKILL_DEVOPS_PROD.md`). В рамках этой задачи настраивается только dev-окружение.
