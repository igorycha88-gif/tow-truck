## 1. Цели и задачи

### 1.1 Бизнес-цель
Видеть во внешней Grafana полное движение клиента по сайту: страница входа,
переходы между страницами, статистика переходов, клики по телефону и WhatsApp,
устройства, UTM-источники визитов, время на странице — с окнами 24ч и 7д.

### 1.2 Согласованный объём (протокол согласования)
- Полный путь: каждая навигация с `from→to`, включая возвраты; дедуп только
  перезагрузок (< 30 с).
- Доп. метрики фазы 1: WhatsApp-клики, устройства (моб/десктоп/планшет),
  UTM на визитах, время на странице.
- Окна метрик: 24ч + 7д.

### 1.3 Метрики успеха
- Переходы и landing видны в `/metrics/tracking` в формате Prometheus.
- Внешний мониторинг подхватывает новые метрики без изменения конфигурации.
- Обратная совместимость: старый payload `/api/visit` принимается.

## 2. Функциональные требования

### 2.1 Клиентский трекер v2 (TASK-FRT-001)

`src/lib/client-tracking.ts` + `src/components/visit-tracker/VisitTracker.tsx`:

1. **ID** (все — `crypto.randomUUID()`, anonymous):
   - `sessionId` — sessionStorage `track:sid` (жизнь = вкладка);
   - `visitorId` — localStorage `track:vid`, TTL 180 дней (запись даты, при
     просрочке — новый);
   - `viewId` — новый на каждый просмотр страницы.
2. **enter-beacon** на каждую навигацию:
   ```json
   { "type": "enter", "page": "<slug>", "from": "<slug|null>",
     "sessionId": "<uuid>", "visitorId": "<uuid>", "viewId": "<uuid>",
     "referrer": "<host|(direct)>",          // только вход вкладки
     "utmSource": "...", "utmMedium": "...", "utmCampaign": "..." }  // только вход
   ```
   `from` — предыдущая страница вкладки (из sessionStorage `track:lastNav`);
   UTM парсятся из `location.search` посадочной страницы (обрезка 100 симв.,
   только `[a-zA-Z0-9._-]`).
3. **leave-beacon** на `pagehide` и `visibilitychange→hidden` (один раз на
   просмотр): `{ "type": "leave", "viewId": "<uuid>", "dwellMs": <int> }`.
   `dwellMs` = now − время enter этого просмотра, клампится 0..1 800 000 (30 мин).
4. **Дедуп**: enter той же страницы < 30 000 мс после предыдущего enter той же
   страницы — не отправляется (F5-шум). Возвраты позже 30 с пишутся.
5. Транспорт: sendBeacon → fallback fetch keepalive (как click-beacon).
   Fire-and-forget, ошибки молчаливые.
6. Старый дедуп `visit:<page>` и `markSourceSent` — удалить, источник теперь
   приходит с enter-входом (совместимость полей сохранена).

### 2.2 API `/api/visit` v2 (TASK-BCK-001)

- Zod-union (старый `{page, referrer?}` валиден как enter без новых полей):
  - `enter`: поля §2.1; `from` — slug-паттерн, опционален; `utm*` — 0..100 симв.
    после санитизации, опциональны; `sessionId`/`visitorId`/`viewId` — uuid
    (8..64 симв.), опциональны.
  - `leave`: `viewId` (uuid, обязателен), `dwellMs` (int 0..1 800 000).
- `leave` → `metricsService.applyLeave()`: `updateMany({ where: { viewId },
  data: { dwellMs } })`; 0 строк — success (fire-and-forget, гонка enter/leave).
- Device: `src/lib/device.ts` — `detectDevice(userAgent)` → `mobile|tablet|desktop`
  (regex: Mobile/Android(iPhone) → mobile; iPad/Tablet → tablet; иначе desktop;
  null-UA → `unknown`). Пишется в Visit и ClickEvent.
- Rate-limit: дефолт `RATE_LIMIT_VISIT_PER_HOUR` 120 → **240** (leave удваивает
  число запросов); env-переменная сохраняется.
- Статусы как сейчас: 201 / 400 / 429 / 500. Логирование request/response
  (method, path, status, duration, type) — обязательно.

### 2.3 WhatsApp-клики (TASK-FRT-002)

`ClickEventsTracker.tsx`: ловить `a[href*="wa.me"]` → `eventType:
'click_whatsapp'`, page — как для tel:. Debounce 5 с — как сейчас.

### 2.4 Экспорт `/metrics/tracking` v2 (TASK-BCK-002)

`promMetricsService.ts`. Все срезы — топ-10 + `other` (пары — топ-10 пар);
«нет данных → блок не рендерится» — как сейчас. Новые метрики:

| Метрика | Тип | Окна | Комментарий |
|---|---|---|---|
| `business_landing_pages_{24h,7d}{page}` | gauge | 24h,7d | вход = первый просмотр сессии (sessionId/legacy-IP) |
| `business_page_transitions_{24h,7d}{from,to}` | gauge | 24h,7d | пары from→to |
| `business_entry_flows_24h{source,landing}` | gauge | 24h | источник × посадочная |
| `business_exit_pages_{24h,7d}{page}` | gauge | 24h,7d | последний просмотр сессии |
| `business_devices_{24h,7d}{device}` | gauge | 24h,7d | по визитам |
| `business_visitors_returning_{24h,7d}` | gauge | 24h,7d | visitorId с визитами до окна |
| `business_whatsapp_clicks_{12h,7d}` + `business_whatsapp_clicks_event` | gauge+events | 12h,7d / 24h | паттерн phone_clicks |
| `business_funnel_{24h,7d}{stage}` | gauge | 24h,7d | visit → content_view → contact_click → lead |
| `business_avg_time_on_page_{24h,7d}` | gauge | 24h,7d | средний dwellMs просмотров с dwell |
| `business_avg_pages_per_session_{24h,7d}` | gauge | 24h,7d | глубина |
| `business_top_dwell_pages_24h{page}` | gauge | 24h | топ-5 по среднему dwell |

Существующие гейджи дополняются парными `_7d` (sessions, page_views,
unique_visitors, avg_session_duration, bounce_rate, leads, conversion_rate,
phone_clicks). Определения воронки:
- `visit` — число сессий (sessionize по sessionId, fallback IP);
- `content_view` — сессии с просмотром страницы вне `{home, politika}`;
- `contact_click` — сессии с ClickEvent `click_phone|click_whatsapp`
  (связка — по sessionId в ClickEvent: **добавить колонку** `sessionId` в
  ClickEvent и передавать из click-beacon);
- `lead` — Order за окно (абсолютное число).
Сессии/лонги считаются по `sessionizeVisits` v2 (ключ = sessionId || IP).

## 4. Критерии приёмки

1. `curl /metrics/tracking` (с ключом) содержит новые метрики; при пустых данных
   блоков новых срезов нет; экспозиция валидна (`promtool check metrics` или парсер).
2. Переход `/ → /uslugi-x → /` фиксируется двумя Visit с `from` и `sessionId`.
3. `leave` обновляет `dwellMs` существующей записи; повторный `leave` — идемпотентен.
4. Клики `tel:` и `wa.me` логируются с `device` и `sessionId`.
5. Старый payload `{page, referrer}` принимается (201).
6. Rate-limit: >240 запросов/час с одного IP → 429.
7. Тесты: unit (device, sessionize v2, воронка, рендер новых метрик, валидаторы),
   API-тесты (enter/leave/старый payload/429), e2e-обновление (metrics.spec.ts).
8. `npm run test && npm run lint && npx tsc --noEmit` — зелёные.
9. Логирование во всех изменённых API/services (request/response, catch).

## 5. Что НЕ входит

- События формы заявки (form_start/submit) — фаза 2.
- Scroll depth — фаза 2.
- Чистка Visit >180 дней — отдельная задача DevOps (риск-нота ADR-014).
- Изменения на стороне внешнего мониторинга (кроме добавления панелей — их
  делает владелец мониторинга по своему ЧТЗ).
