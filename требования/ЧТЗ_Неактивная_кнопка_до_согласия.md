# ЧТЗ — Неактивная кнопка отправки до согласия + логирование согласия (152-ФЗ)

- **Дата:** 2026-08-31
- **Маршрут:** 1 — АНАЛИТИК → РАЗРАБОТЧИК → ТЕСТИРОВЩИК → DEVOPS
- **Тип:** малая задача (§6)

## Задача

1. Кнопка «Отправить заявку» — **неактивна** (disabled), пока не отмечен чекбокс
   «Я согласен на обработку персональных данных».
2. Согласие **логируется в системе**: фиксируется в БД с меткой времени (`consentAt`)
   и в структурном логе (pino) при создании заявки. Это требование 152-ФЗ
   (доказуемость факта и времени получения согласия).

## Изменения

| Файл | Изменение |
|------|-----------|
| `src/components/forms/OrderForm.tsx` | `watch('consent')` → `disabled={!consent}` на кнопке |
| `prisma/schema.prisma` | `Order.consentAt DateTime` (NOT NULL) |
| `prisma/migrations/…add_order_consent_at/` | ADD COLUMN + бэкфилл `consentAt = createdAt` (все прошлые заявки отправлялись с обязательным согласием) + SET NOT NULL |
| `src/services/ordersService.ts` | `consentAt: new Date()` при создании; в лог `Order created` добавить `consent: true, consentAt` |
| `src/types/index.ts` | `OrderRecord.consentAt: Date` |
| Тесты | ordersService.test.ts (сохранение + лог consentAt), e2e home.spec.ts (кнопка disabled → чекбокс → enabled) |

Zod-схема не меняется: `consent: z.literal(true)` уже гарантирует согласие.

## Критерии приёмки

1. Кнопка «Отправить заявку» disabled, пока чекбокс согласия не отмечен; после
   отметки — активна.
2. Каждая заявка в БД содержит `consentAt` (время согласия = время отправки).
3. Существующие заявки получили `consentAt` = `createdAt` (бэкфилл, ничего не потеряно).
4. В структурном логе создания заявки есть факт согласия и метка времени.
5. `npm run test && npm run lint && npx tsc --noEmit` — без ошибок; e2e обновлены.
6. Полная пересборка dev + smoke-тест.
