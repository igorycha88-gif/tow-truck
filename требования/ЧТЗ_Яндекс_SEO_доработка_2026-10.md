## 2. Задачи разработки

### TASK-Я-01. Метрика: убрать двойной просмотр при загрузке
**Приоритет:** P0 · **Оценка:** 1 ч · **Зависимости:** —
**Проблема.** `ym(..., 'init', {...})` без `defer` сам отправляет просмотр, а `MetrikaRouteTracker`
в `useEffect` при первом рендере шлёт ещё один `hit` → каждая страница входа считается дважды,
искажаются отказы и глубина. В `hit` не передаётся `referer` — внутренние переходы без источника.
По [справке для SPA](https://yandex.ru/support/metrica/code/counter-spa-setup.html): инициализация
с `defer: true`, все просмотры — через `hit`.

**Файлы:** `src/lib/seo/metrika.ts`, `src/components/tracking/MetrikaRouteTracker.tsx`.

**Изменения:**
1. В `init` добавить `defer: true` (остальные параметры не менять).
2. `MetrikaRouteTracker`: отправлять `hit` на первом рендере и при каждой смене `pathname`;
   хранить предыдущий URL в `useRef`, передавать `{ referer: prevUrl, title: document.title }`;
   не слать повторный `hit` на тот же URL.
3. `url` — абсолютный (`location.href`), чтобы в отчётах не было относительных адресов.

**Критерии приёмки:**
- [ ] Unit `metrika.test.ts`: в сниппете есть `defer:true`.
- [ ] Unit `MetrikaRouteTracker.test.tsx`: первый рендер — 1 вызов `hit`; смена pathname — +1 вызов с `referer` предыдущей страницы; повторный рендер с тем же pathname — 0 вызовов.
- [ ] Ручн. `?_ym_debug=1`: загрузка главной — ровно один просмотр; переход главная → `/ceny` по ссылке — ещё один.

### TASK-Я-02. Навигационная цепочка по требованиям Яндекса
**Приоритет:** P1 · **Оценка:** 1,5 ч · **Зависимости:** —
**Проблема.** Имена в цепочке — полные H1 (`page.h1`, `hubH1`: «Эвакуатор в Восточном округе Москвы (ВАО)»).
Яндекс исключает из навигационной цепочки элементы на главную, короче 4 символов и «слишком
длинные», рекомендует до 3 элементов ([Навигационные цепочки](https://yandex.ru/support/webmaster/ru/supported-schemas/navigation-links)).
У услуг после исключения «Главной» остаётся один элемент — цепочки в сниппете не будет.

**Файлы:** `src/types/service-page.ts` (поле `breadcrumbName?: string`), `src/config/geo/types.ts`
(`hubBreadcrumbName: string`), `src/config/geo/index.ts`, `src/components/pages/ServicePage.tsx`,
конфиги 16 услуг (поле `breadcrumbName`).

**Изменения:**
1. Локация — `loc.name` («Марьино»); хаб — короткое имя («ВАО Москвы», «Восток Подмосковья»);
   услуга — `breadcrumbName` («После ДТП», «С лебёдкой», «Цены»).
2. Для услуг добавить промежуточный элемент «Услуги» → `/#services` не нужно (якорь на главную —
   исключается Яндексом); цепочка услуги остаётся «Главная → Услуга», это ожидаемо.
3. Видимые крошки и JSON-LD используют одни и те же имена.

**Критерии приёмки:**
- [ ] Unit: у всех 123 страниц в `BreadcrumbList` ≤ 3 элементов, каждый `name` 4–40 символов, все `item` на `xn--80aae0ai8cwa4cza.online`.
- [ ] Ручн.: валидатор микроразметки Вебмастера — 0 ошибок на `/evakuator-marino`, `/evakuator-vao-moskvy`, `/ceny`.

### TASK-Я-03. Гео-страницы: вывести из «малоценных» (без выгрузок Вебмастера)
**Приоритет:** P1 · **Оценка:** 2 ч скрипт и отбор + 1 ч/страница · **Зависимости:** 2–3 недели после
выкатки перелинковки (глубина могла быть основной причиной)
**Основание:** у Яндекса есть статус «малоценная или маловостребованная»; рекомендация — убрать дубли
и изменить контент под запросы ([справка](https://yandex.ru/support/webmaster/site-indexing/low-demand.html)).
Гео-страницы на ~46–55% уникальны, 312–400 слов (минимальные: `evakuator-ilinskij` 312, `bykovo` 313,
`tomilino` 320, `oktyabrskij` 322, `caricyno` 324). Выгрузок Вебмастера нет (владелец, 23.10).

**Шаг 1. Аудит-скрипт.** `scripts/seo-geo-audit.ts` (`npx tsx scripts/seo-geo-audit.ts > geo-audit.csv`):
по 107 гео-страницам — `slug; направление; слов всего; слов в уникальных блоках (lead + localIncluded +
localFaq + sections); доля уникального, %; глубина от главной`. Подсчёт — чистая функция в
`src/lib/seo/geo-audit.ts` с unit-тестом.

**Шаг 2. Спрос.** Для нижней трети — Wordstat («Подбор слов», регион Москва и область):
«эвакуатор <локация>» и разговорная форма; сначала выгрузки из `данные из вордстат/`.

**Шаг 3. Поведение.** Метрика (счётчик 111456265): «Источники → Поисковые системы» → группировка
«Страница входа», фильтр «Яндекс», 8 недель. Локации с 0 входов из поиска — кандидаты.
(Данные корректны после Я-01.)

**Отбор волны (≤ 15 страниц):** доля уникального < 50% или объём < 340 слов, **и** спрос есть
(Wordstat ≥ 10/мес или входы из поиска). Доработка по Алгоритму 5 `SKILL_SEO.md`: +1 уникальная
H2-секция (ТЦ, развязки, СТО/дилеры, типичные сценарии), +1 `localFaq` с локальным фактом,
объём ≥ 500 слов, ключ из Wordstat в H2/FAQ.
**Локации без спроса** (Wordstat < 10/мес и 0 входов за 8 недель) — не наращивать; вопрос владельцу:
301 на хаб и удаление из реестра.

**Шаг 4. Блок Coverage по данным.** Сейчас под хабом — «первые 3 локации по списку»
(`coverageTopLocalityLinks`). Заменить на 3 локации с наибольшим числом входов из Яндекса (Метрика)
или частотой Wordstat — явным списком в `src/config/seo-links.ts`.

**Шаг 5. Статус Яндекса, когда появится выгрузка** (владелец, ~5 минут, через 2 недели после релиза):
Вебмастер → «Индексирование» → «Страницы в поиске» → «Исключённые страницы» → фильтр
«Малоценная или маловостребованная страница» → скачать таблицу; там же «Все страницы» → скачать.
Положить в `требования/` с датой в имени. С выгрузкой в приоритет волны — страницы с этим статусом.

**Критерии приёмки:**
- [ ] `geo-audit.csv` по 107 страницам; unit-тест функции подсчёта зелёный.
- [ ] Список волны с обоснованием (скрипт + Wordstat + Метрика) приложен к PR.
- [ ] Тест в `geo/index.test.ts`: страницы волны ≥ 500 слов, уникальные блоки ≥ 55%.
- [ ] Через 4 недели: рост входов из Яндекса на страницы волны; после выгрузки — меньше «малоценных».

### TASK-Я-04. FAQ-разметка: убрать неверное ожидание

**Проблема.** Комментарий в `src/lib/seo/json-ld.ts` («FAQPage — расширенный сниппет в выдаче Яндекса»)

Наш FAQ (3–5 вопросов на странице) под это не подходит, а `QAPage` предназначен для вопросов
пользователей — переделывать FAQ в `QAPage` не нужно.
**Файлы:** `src/lib/seo/json-ld.ts` (комментарий), `SKILL_SEO.md` (раздел про JSON-LD: FAQPage
сниппетов ни в Яндексе, ни в Google не даёт; разметку оставляем, «напрямую семантическая разметка
не влияет на ранжирование» — [справка](https://yandex.ru/support/webmaster/schema-org/semantic-faq.html)).
- [ ] Комментарий и скилл исправлены; разметка `FAQPage` без изменений.
